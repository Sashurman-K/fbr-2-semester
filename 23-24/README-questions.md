Docker появился в 2013 году как решение проблемы "на моей машине работает". До этого использовали виртуальные машины, но они были слишком тяжёлыми. Docker сделал контейнеризацию лёгкой и доступной.

# ЧТО БЫЛО ДО DOCKER?
Первым шагом стало появление системного вызова chroot в Unix V7.
Появление Jails во FreeBSD. Они расширили идею chroot, добавив изоляцию не только файловой системы, но и других критически важных компонентов: собственный hostname, выделенный IP-адрес, изолированную сеть и свою таблицу пользователей.
В 2004 году компания Sun Microsystems представила технологию Zones для своей операционной системы Solaris.
Появление LXC (Linux Containers) в 2008 году. LXC объединил две ключевые технологии: namespaces: обеспечивают изоляцию, давая процессу свой собственный вид системы (изолированная сеть, список процессов и т.д.). cgroups (Control Groups): обеспечивают управление ресурсами, ограничивая количество процессорного времени, памяти и т.д., которое может использовать группа процессов.

# ПОЧЕМУ DOCKER?

Docker — платформа для контейнеризации приложений, которая предоставляет ряд преимуществ, упрощающих разработку, развёртывание и эксплуатацию ПО.

## Портативность.
 Контейнеры работают одинаково в любом окружении, где установлен Docker — на локальном компьютере, в дата-центре, облаке или на другом устройстве. Это исключает проблему «у меня работает, а на сервере нет» и упрощает перенос приложений между средами.

## Скорость развёртывания.
Запуск контейнера занимает секунды, так как не требуется загрузка отдельной операционной системы — контейнеры используют общее ядро хост-системы. Это ускоряет процессы тестирования, выпуска новых версий и развёртывания приложений.

## Эффективное использование ресурсов.
 Контейнеры потребляют меньше ресурсов, чем виртуальные машины, так как не требуют отдельной операционной системы. На одном сервере можно запустить десятки контейнеров, что снижает затраты на инфраструктуру.

## Изоляция приложений.
Каждый контейнер работает в своём пространстве имён и изолирован от других контейнеров и хост-системы. Это предотвращает конфликты между зависимостями, обеспечивает безопасность и стабильность работы приложений: если одно приложение даст сбой, остальные продолжат функционировать.

## Упрощение масштабирования.
При росте нагрузки можно быстро запустить дополнительные экземпляры контейнера и распределить между ними трафик. Когда нагрузка спадёт, лишние контейнеры легко остановить. Docker поддерживает горизонтальное масштабирование, что особенно полезно для микросервисной архитектуры и систем с переменной нагрузкой.

# ЧТО такое Deamon Docker
Docker Daemon (докер демон) — это фоновый процесс (dockerd), который управляет всеми операциями Docker: образами, контейнерами, сетями, томами. Он работает постоянно, слушает API-запросы (например, от Docker CLI) и взаимодействует с ядром ОС через системные вызовы

 Единая точка отказа. Основная проблема Docker Daemon — это его остановка или недоступность, из-за которой перестают работать все контейнеры и любые команды Docker.

# Надстройки над docker
## Оркестрация: Управление армией контейнеров
Оркестраторы решают главную проблему Docker на продакшене: что делать, когда контейнер падает, как распределить нагрузку и связать контейнеры на разных серверах.

Kubernetes (K8s) — Безусловный лидер: Это стандарт де-факто в индустрии. K8s не просто управляет контейнерами, он поддерживает декларативный подход: вы описываете желаемое состояние системы (например, "у меня должно работать 5 копий приложения"), а K8s сам обеспечивает его.

Плюсы: Огромное комьюнити, поддержка всеми облачными провайдерами, решает 99% задач микросервисной архитектуры.

Минусы: Очень высокая сложность порога входа ("горный склон для обучения").

Docker Swarm — "Родной" оркестратор: Встроен прямо в Docker.

Плюсы: Невероятно прост в настройке (docker swarm init), идеален для небольших команд и проектов, где не нужна вся мощь K8s.

Минусы: Слабее в вопросах автоматического масштабирования и более сложной сетевой политики.

Nomad — Универсальный солдат: От компании HashiCorp.

Плюсы: Может управлять не только контейнерами Docker, но и обычными исполняемыми файлами, Java-приложениями и даже виртуальными машинами. Очень легковесный.

Минусы: Меньше готовых решений "из коробки", чем у K8s.

## GUI-панели: Визуальный контроль над контейнерами
Эти инструменты позволяют управлять Docker'ом через браузер или десктопное приложение, избавляя от необходимости помнить все команды.

Portainer: Универсальный выбор для начинающих и профессионалов. Легко ставится как один контейнер и открывает веб-интерфейс, где можно видеть логи, запускать новые контейнеры, управлять сетями. Особенно полезен для перехода от Docker к Kubernetes, так как умеет дружить с обоими.

Docker Desktop: Официальное приложение от Docker для Windows и Mac. Включает в себя сам движок и простой графический интерфейс для локальной разработки.

Lens: Самый популярный "IDE для Kubernetes". Очень мощный инструмент для профессиональных разработчиков и DevOps, которые ежедневно работают с кластерами.

Rancher: Уже не просто панель, а целая платформа для управления множеством K8s-кластеров в режиме 24/7. Используется в крупных компаниях.

## CI/CD и Безопасность: Автоматизация и защита
Эти инструменты встраиваются в процесс разработки, делая его быстрее и безопаснее.

CI/CD (Jenkins, GitLab CI, GitHub Actions): Позволяют автоматически собирать Docker-образ, проверять его и развертывать на сервере при каждом новом коммите разработчика.

Безопасность (Сканеры): Инструменты вроде Trivy, Snyk, Docker Scout анализируют ваши образы на предмет устаревших библиотек с известными уязвимостями (CVE). Они встраиваются прямо в CI/CD и не пустят "код с дырами" на прод.

## Мониторинг и Логирование: Смотрим внутрь системы
Когда контейнеров много, стандартный docker logs становится бесполезен.

The "Golden Stack" (Prometheus + Grafana + cAdvisor): Это промышленный стандарт.

cAdvisor автоматически собирает метрики с контейнеров (CPU/память/сеть).

Prometheus забирает и хранит эти метрики.

Grafana рисует красивые графики и дашборды, а также умеет отправлять предупреждения (alert'ы) в Telegram или Slack, если у контейнера закончилась память

# Альтернативы Docker
Podman — главный конкурент, созданный Red Hat. В отличие от Docker, он работает без демона (daemonless): контейнеры запускаются как дочерние процессы напрямую из CLI. Это делает его идеальным для серверов с высокими требованиями к безопасности.

Ключевая особенность: Полная поддержка rootless-контейнеров (запуск без прав root) "из коробки", в то время как в Docker это режим требует донастройки.

Совместимость: Является полным аналогом команд Docker (alias docker=podman). Работает с Dockerfile и Docker Hub.

Экосистема:
Buildah: сборка образов без демона.
Podman Desktop: GUI-альтернатива Docker Desktop с поддержкой Kubernetes и лицензией Apache 2.0.

Минусы: Нативная поддержка только Linux (на macOS/Windows через виртуальную машину), сложности с пробросом сетевых портов в rootless-режиме
